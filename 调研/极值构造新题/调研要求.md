# 新极值构造题调研要求

## 背景

项目 `E:\Project\AI_OneShot_Bench` 是大模型限时评测。受测模型无人值守、独立作答，限时 60 分钟。算法竞赛类里有两道“极值构造题”：模型提交一个构造，评测精确算出目标值，再按锚点表折算成 0–100 分。

现有两题的题面：

- `算法竞赛\极值构造\正负一序列的自相关能量最小化.md`（LABS，N=251）
- `算法竞赛\极值构造\单位正方形内最小三角形面积最大化.md`（Heilbronn，30 点）

用户觉得 LABS 这题“有点野”，看起来随机性太大。四个模型的实测结果：

| 模型 | 能量 E | 得分 |
|---|---:|---:|
| Claude Sonnet 5.5 | 3853 | 75.3 |
| Claude Opus 5.5 | 4061 | 58.0 |
| GPT 6.1 Sol | 4253 | 43.4 |
| Claude Fable 5.1 | 4293 | 41.2 |

计分锚点（E→分）：10501→0，6301→4，5253→10，4845→18，4501→30，4205→46，3941→68，3701→88，3581→100（已知最好值）。

## 要找什么

找**其他方向**的极值构造题。不要 LABS 及其变体，也不要 Heilbronn 及其变体。用户的要求：

1. **题要够大**：实例规模大，60 分钟内远远做不到最优，做不到封顶。
2. **多种方法，优化空间很大**：从简单方法到好方法，目标值有很长的提升路程。
3. **方法不同，差距要明显**：不同层级的方法拉开明显差距，分数主要反映用了什么方法、改进得好不好，而不是运气。
4. **最好受初始方法影响较小**：
   - 同一方法换随机种子，结果接近；
   - 一开始选了较差的方法或起点，后面仍能靠改进追上来，不会被第一步锁死。

## 尽量避免运气误差（用户追加，优先级最高）

分数要反映方法和改进，不能取决于碰巧撞到好解。LABS 的反例：Sonnet 的 CPU 长跑在 E=4317 停了约 17 分钟，然后在一次下降里直接跳到 3853，换来 30 多分的领先；而同族方法、速度更快的 GPU 搜索都没有接近这个值。

- **淘汰“高尔夫球场”型地形**：好解是孤立的深坑、结果靠撞大运的题，即使层间差距看起来很大，也不要推荐。
- **优先选这样的题**：目标值随投入平稳提升，好解多而连续；同一方法跑得越久结果越好，且多次运行的结果收窄。
- **实测时要报告**：
  - 同一方法、同一预算、至少 5 个种子的结果，用你的建议锚点换算成分数后的最高最低差（参考目标：不超过约 5 分）；
  - 层间差距换算成分数（参考目标：至少约 15 分）；
  - 单次运行的“目标值—时间”曲线是平稳爬升，还是长时间不动后突然跳变；
  - 预算加倍后，均值和波动怎么变。
- 上面的数字是参考目标，不是硬线。达不到时如实写，并说明差多少。
- 锚点也要配合这一点：不要把分数陡升段放在主要靠运气才能到达的区间。

## 硬条件

- **能精确判分**：提交是一个构造，评测用确定的程序（整数或有理数精确计算）得出目标值，不需要人判断。提交文件大小合理。
- **能设定锚点**：有已知最好值（文献、公开纪录表）或能实测出可靠的高水平基准，并能列出方法层级。
- **不能靠背或套公式**：公开纪录表或现成闭式构造不能直接给出高分解。模型作答时不能联网。
- **题面能写短**：一两段话能讲清定义和提交格式，不需要附大量数据。如果必须提供实例数据，说明生成方式和大小。
- **作答环境**：Windows 11，14 个逻辑处理器，共用 RTX 4080，g++、Python 3.12（numpy、scipy、sympy、mpmath、pandas）、Node；不能联网，不能安装软件，可以自由写和运行程序。

## 要做的

1. 广泛调研你负责的方向（查论文、公开纪录表、竞赛题），列出候选题。
2. 选出最好的 **3 道**，在本机做小实验，用实测判断它们是否满足上面的要求。每道题至少：
   - 实现 2–3 个不同层级的方法（例如简单启发式、局部搜索、更强的结构化搜索）；
   - 每个方法用相同的时间预算（例如 5–10 分钟）跑 3 个以上随机种子；
   - 报告层级之间的差距和同一方法内种子间的波动，算出“层间差距 ÷ 种子波动”；
   - 试一下从差的起点继续改进能不能追上来。
3. 对照 LABS N=251：用同样方式估计它的这个比值，判断候选题是否确实比它稳。如果时间不够，至少给出文献或推理依据，并注明没有实测。
4. 不写题面，不改任何已有文件，只交报告。

## 实验的资源限制

- 同一时间不超过 8 个线程；单次实验不超过 10 分钟；GPU 只做必要的小实验。
- 实验前运行 `python E:\Project\AI_OneShot_Bench\orchestrator\timer.py status` 和 `python E:\Project\AI_OneShot_Bench\orchestrator\grading.py status`。有题正在作答或正在评分时，不跑重负载实验，只做调研和小规模计算。这两条是只读命令，其他 timer、grading 命令一律不要运行。
- 实验代码和数据放在你自己的工作目录，不碰 `H:\AI_OneShot_Model\`、`orchestrator\` 和 `Grading\`。

## 报告格式

写成中文 Markdown，存到给你指定的路径，开头先给结论。每道候选题写清楚：

| 项 | 内容 |
|---|---|
| 定义 | 能直接写进题面的数学定义、实例规模、目标方向 |
| 提交与判分 | 提交格式，如何精确计算 |
| 已知最好值 | 数值和来源链接 |
| 方法层级 | 各层方法及其达到的目标值，注明是实测还是文献值 |
| 实验数据 | 每个方法各种子的结果、层间差距、种子波动、比值、预算 |
| 初始方法影响 | 换起点、换方法后能否追上 |
| 风险 | 能否靠背或套公式、60 分钟内会不会被做到封顶、实现难度 |
| 建议锚点 | 目标值到分数的大致对应 |

最后按推荐顺序排名，说明为什么比 LABS 更合适。实测和文献要分清，没验证的不要写成结论。
