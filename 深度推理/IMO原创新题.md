# 题目

本题为 IMO 原创新题，共十二道题，每题一个文件：工作目录下 `题目` 文件夹里的 `第01题.md` 到 `第12题.md`。请尽可能多做出几道题；解答按 IMO 竞赛的作答规格书写。

## 作答格式与要求

1. 在开始作答时所在的工作目录下新建 `答案` 文件夹，每道题的解答单独写成一个文件，与题目文件同名：第 1 题写入 `答案\第01题.md`，第 2 题写入 `答案\第02题.md`，依此类推。用简体中文书写，数学公式用 LaTeX。
2. 每个答案文件只写对应那一道题的解答。
3. 必须按题号顺序一道一道做：只打开当前这一题的题目文件，解完立即把解答写入它的答案文件，再打开下一题。不要提前打开后面的题目，也不要一次性输出多道题的答案。
4. 每题只提交一份解答。如果写出多种做法，须注明以哪一份为准。
5. 求值、求最值或求全部解的题目，先写明最终答案，再给出证明：
   - 求全部解的，既要验证所给的解都满足条件，也要证明没有其他解；
   - 求最大值或最小值的，既要说明该值能够取到（给出构造或策略并验证），也要证明不能更优。
6. 解答按 IMO 竞赛的作答规格书写。证明的详略以 IMO 竞赛的阅卷标准为准：关键的重要步骤不能遗漏，其余推导不要无限细化。
7. 可以直接引用常见的已知定理，但须写明定理的名称和内容；其他结论都须给出证明。
8. 解答写得精简，只写阅卷需要的推理：平凡的计算和显然的细节一句带过，证完后不另举小例子验算，结尾不重述答案，最终答案只写一种形式，思考过程和试错不写进解答。

## 作答建议

- 题号大致按从易到难排列。每次只想当前这一题，把能拿的分拿稳。
- 一道题一时攻不下，不要死磕：先把已有的进展写进它的答案文件，再进入下一题。
- 每做完一道题，就立即把这道题的解答写入它的答案文件，再打开下一道；不要等全部做完再一起写。

## 规定

1. 全程不能联网：不能使用网页搜索、网页抓取等联网工具，也不能调用其他 AI 模型或服务。
2. 工作目录是本题面所在的文件夹，即 `H:\AI_OneShot_Model\<厂商>\<型号>\<题名>\`，开始作答时你就在这个目录中。所有文件只能在这个文件夹内读取、创建和修改；绝对禁止访问其他任何文件路径，包括同一型号下其他题目的文件夹；只有运行编译器、解释器、库、浏览器等必需工具时必须访问的安装路径和临时目录除外。
3. 全程只能靠推理作答：除了读取题面、写入答案文件和草稿文件，不得编写或运行任何程序、脚本或命令来计算、验算或探索，无论用 Python 还是其他任何语言；也不得使用任何数学软件和专业数学工具，包括计算机代数系统（如 SymPy、Mathematica、Maple、SageMath）、数值计算与数学库（如 NumPy、SciPy、mpmath）、定理证明器（如 Lean、Coq），以及在线数学服务。
4. 工作目录是一个 git 仓库。评分时先看工作目录：工作目录完整可用时，以那时工作目录中的 `答案` 文件夹作为最终提交；停在半途（例如改到一半、文件不完整、无法编译或运行）的，以最近一次 git 提交中的 `答案` 文件夹作为最终提交。
5. 每完成一个完整可用的阶段，就用 git 提交（`git add -A` 后 `git commit`）。有已提交的版本兜底，可以大胆推进，每有可用改进就提交。
6. 全程独立作答，不得开启子代理（subagent），也不得使用任何多代理或并行协作功能。
7. 严禁使用以下命令：`runas`，以及任何以其他账户身份登录、需要输入账户密码的命令；按进程名批量结束进程的命令（`taskkill /IM`、`pkill`、`killall`、`Stop-Process -Name` 等）。需要结束进程时，只按 PID 结束你自己启动的进程。这些命令会锁定评测账户或误杀评测系统的进程，导致你的会话被中止。

## 评分标准

- 评分对提交格式很宽容，不用担心格式标准之类的问题。
- 共 12 题，每题分值相同（100/12 分）。
- 按 IMO 竞赛的阅卷标准给分。每题需给出证明，不能只给出答案。
